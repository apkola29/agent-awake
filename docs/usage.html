Install

Requires VS Code 1.93 or newer, or an editor based on it, such as Cursor, Windsurf or VSCodium. Works on Windows 10/11, macOS and Linux desktops.

  1. Download agent-keep-awake-1.0.0.vsix from the latest release.
  2. Install it in either of these ways:
    • From a terminal: code --install-extension agent-keep-awake-1.0.0.vsix (use cursor, windsurf or codium for those editors).
    • In the editor: open the Extensions view, click the … menu, choose Install from VSIX… and pick the file.
  3. A coffee cup appears at the right-hand end of the status bar. You’re done: from now on your computer won’t go to sleep while VS Code is open.

What the status bar shows

Hover over the icon for a short explanation and quick links. Each state has its own icon, so you don’t need to tell them apart by colour.

Turning it off and on

Click the icon. That saves agentKeepAwake.enabled in your user settings, so every VS Code window follows along and the choice survives restarts.

The same actions are in the Command Palette (Ctrl+Shift+P, or Cmd+Shift+P on a Mac). Type Agent Keep-Awake to find:

  • Toggle On/Off
  • Turn On (Keep Machine Awake)
  • Turn Off (Allow Sleep)
  • Show Status: what it’s doing right now, and which OS mechanism it uses
  • Show Log: the extension’s log, useful when something goes wrong

You can bind any of these to a keyboard shortcut in Keyboard Shortcuts.

Choosing a mode

Which should you pick? If you’re not sure, keep the default. Always can’t miss anything. Activity saves battery if VS Code stays open after the work is done.

Always (default)

The computer stays awake the whole time VS Code is open. It’s the simplest and most dependable option, because an agent that’s thinking quietly for twenty minutes is covered too.

Activity

The computer stays awake only while something is happening in that VS Code window, then for agentKeepAwake.activityTimeoutMinutes (default 30) after the last sign of activity. These count as activity:

  • Edits to documents and notebooks, whether you or an agent made them.
  • Files changing on disk in the workspace, for example when a CLI agent such as Claude Code or Codex writes them. Changes inside .git are ignored, so routine git housekeeping doesn’t keep you awake.
  • A terminal command that is still running. This needs VS Code’s shell integration, which is on by default for bash, zsh, fish and PowerShell. A CLI agent running in the terminal counts as one long command.
  • A running task or debug session. Background (watch) tasks count only when they start, because they never finish.

Turn it on with "agentKeepAwake.mode": "activity", or search for Agent Keep-Awake in the Settings editor.

Settings

SettingDefaultDescription
agentKeepAwake.enabledtrueThe main switch. Clicking the status bar icon changes it.
agentKeepAwake.mode"always""always" or "activity"; see Choosing a mode.
agentKeepAwake.activityTimeoutMinutes30Activity mode only: how long to stay awake after the last activity (1–1440).
agentKeepAwake.keepDisplayOnfalseAlso keep the screen on. Leave it off to let the display sleep and lock as usual while the computer keeps working.
agentKeepAwake.showStatusBarItemtrueShow the icon in the status bar. Keep-awake still works when it’s hidden.

Example settings.json for a battery-conscious laptop:

{
  "agentKeepAwake.mode": "activity",
  "agentKeepAwake.activityTimeoutMinutes": 20
}

Remote development

Agent Keep-Awake runs on your local computer by default, even in Remote-SSH, WSL and Dev Containers, because that’s the laptop that would fall asleep and drop the connection. The remote side needs nothing.

If you use VS Code in a browser, for example through a Remote Tunnel, there’s no local side to run on, so it runs on the remote machine and keeps that machine awake. That suits a desktop at home that you reach from somewhere else.

To keep the remote machine awake instead of your local one, add this to your user settings:

"remote.extensionKind": {
  "apkola29.agent-keep-awake": ["workspace"]
}

The tooltip on the icon always tells you which machine it is keeping awake.

Checking that it works

The quickest check is to hover over the cup, or run Agent Keep-Awake: Show Status. To see it from the operating system’s side:

Windows

In a terminal opened as administrator:

powercfg /requests

Under SYSTEM: you’ll see a [PROCESS] line ending in powershell.exe. That’s the helper. With keepDisplayOn it also appears under DISPLAY:.

macOS

pmset -g assertions | grep caffeinate

Look for PreventUserIdleSystemSleep owned by caffeinate.

Linux

systemd-inhibit --list

Look for VS Code (Agent Keep-Awake) with sleep in the What column.

Good to know

  • Closing the lid or pressing the power button still puts the computer to sleep. Those are explicit choices, so the OS doesn’t let apps override them. For lid-closed work, set your OS’s lid action to “do nothing”, or plug in an external display.
  • Your screen still turns off and locks. Only the system is kept awake, unless you turn on keepDisplayOn.
  • Battery. A computer that’s awake uses power. For long runs on a laptop, plug in, or use activity mode so it can sleep afterwards.
  • Several windows. Each VS Code window holds its own request, and the computer stays awake until the last one lets go.
  • VS Code closes or crashes. The helper exits by itself and the OS drops the request. Nothing is left behind.
  • Copilot’s own blocker. Recent Copilot versions block sleep while a Copilot request is in progress. The two don’t conflict; the OS simply counts both.

Troubleshooting

Start with Agent Keep-Awake: Show Log. It records which helper started, its process ID, and any error.

The icon shows a warning

  • Windows, “Constrained Language Mode”. Your organisation has locked down PowerShell, and that blocks the call to the Windows power API. Ask IT, or use the keep-awake tool they approve.
  • Windows, “powershell.exe was not found”. Windows PowerShell has been removed. If PowerShell 7 is installed and pwsh is on your PATH, it’s used instead.
  • Linux, “Neither systemd-inhibit nor gnome-session-inhibit was found”. Your desktop uses neither systemd nor GNOME’s session manager, so it isn’t supported yet. Please open an issue and name your distribution and desktop.

The computer still went to sleep

  • Was the lid closed or the power button pressed? Both override keep-awake on purpose.
  • In activity mode, was there a long, quiet stretch (no edits, no running commands) longer than the timeout? Raise activityTimeoutMinutes, or use always mode.
  • Some company policies force sleep or hibernation regardless of what apps ask. powercfg /requestsoverride (Windows) or a policy can also make the OS ignore requests. Check with IT.
  • Check the OS side as described in Checking that it works while VS Code is open.

Uninstalling

Uninstall it from the Extensions view, or run code --uninstall-extension apkola29.agent-keep-awake. It never changes system settings, so there is nothing to clean up. The helper stops when the extension does.

FAQ

Does it move my mouse or press keys?

No. It makes the same supported request a video player or presentation app makes, through each OS’s power management API.

Does it change my power plan or energy settings?

No. It holds a temporary request that the OS drops automatically when the helper exits, so there’s nothing to restore.

How much CPU and memory does it use?

Effectively none. The helper waits on a pipe without polling. Measured on Windows 11 over ten minutes, it used 0.05 seconds of CPU in total (under 0.01% of one core) and about 7 MB of memory. The extension itself has no timers in the default mode and doesn’t listen for activity events unless you choose activity mode.

Does it send any data anywhere?

No. It has no telemetry and makes no network requests. The source is a few hundred lines of JavaScript with no dependencies.

Will my screen still lock?

Yes, unless you turn on keepDisplayOn. Locking and screen-off don’t stop your agents; only sleep does.

Why does it need PowerShell on Windows?

The Windows power API can only be called from native code. Rather than ship a binary of its own, the extension calls the API through Windows PowerShell, a signed Microsoft program that’s already installed. Nothing is compiled, downloaded or written to disk. You can read the exact one-line script in src/keepAwake.js.

Does it work with Claude Code, Codex, Gemini CLI or Copilot CLI in the terminal?

Yes. In the default mode the computer stays awake whatever you run. In activity mode, a CLI agent running in VS Code’s integrated terminal counts as activity while it runs, and so do the files it writes.
