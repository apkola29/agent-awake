The problem

One evening, two ways it can go

Without it

  1. 6:10 pmYou hand agent mode a three-hour refactor, with four subagents fanning out across the codebase. The plan looks good. You head home.
  2. 6:40 pmThirty minutes without a keypress. As far as your operating system can tell, nobody is there, so it goes to sleep.
  3. 6:40 pmEverything stops mid-step: the model request, the test suite in the terminal, the SSH session to your dev box.
  4. 8:55 amYou open the lid to a half-applied diff, a dead terminal and a “Reconnecting…” banner. Half an hour of a three-hour job got done.

With Agent Keep-Awake

  1. 6:40 pmThe screen turns off and locks, as usual. The computer keeps working.
  2. 9:05 pmThe last subagent reports back and the tests pass.
  3. 8:55 amYou read the summary over coffee.

The cause

Sleep timers count keystrokes, and agents don’t type

Sleeping is not locking. A locked computer, or one with its screen off, keeps running. A sleeping one stops everything: processes, network connections and timers.

Your operating system decides you’ve walked away by watching the keyboard and mouse. For decades that was a reasonable guess, because if nobody was typing, nothing was happening.

Agentic coding broke that guess. An agent reads files, edits code, runs builds and calls models for an hour or more without touching your keyboard. To the OS, a laptop doing a three-hour agent run looks exactly like a laptop someone forgot about.

Work laptops make this worse. Sleep timeouts of 10 to 30 minutes are common, and they’re often set by policy, so you can’t just change them.

The workarounds

What people try instead

The Copilot behaviour is described in microsoft/vscode#276546 and was added in this commit. It uses the proposed env.power API, which Marketplace extensions can’t use.

WorkaroundThe catch
Change the power settingsAffects everything, all the time. It’s easy to forget to change back, and then the laptop never sleeps and cooks in your bag. IT often locks these settings anyway.
A mouse jiggler (app or USB dongle)It pretends to be you, which also defeats your screen lock. Many workplaces don’t allow them.
caffeinate, PowerToys Awake, AmphetamineGood tools, but each is separate, manual and works on one OS only. You have to remember to start them, and to stop them.
The sleep blocker built into CopilotSince February 2026, Copilot in VS Code blocks sleep while a Copilot request is in progress and lets go two minutes after it finishes. It doesn’t cover long tool runs between requests, agents that run in the terminal (Claude Code, Codex, Copilot CLI, Gemini CLI) or other chat extensions.

The fix

Ask the OS properly, and let go cleanly

Agent Keep-Awake uses the supported method on each operating system to say “don’t sleep right now”. It holds that request while VS Code is open and releases it the moment VS Code isn’t. It was built around a few rules:

  • About 0% CPU. A tiny helper that ships with your OS sits waiting on a pipe. There’s no polling, no timer and no network access.
  • Nothing to undo. It never changes power settings, so a crash can’t leave you with a laptop that won’t sleep.
  • When VS Code goes, the block goes. If VS Code quits or crashes, the helper notices and exits, and the OS drops the request. The tests hard-kill the owning process on Windows, macOS and Linux to prove it.
  • Your screen still locks. Only the system is kept awake. The display sleeps as usual unless you ask otherwise.
  • Closing the lid still means sleep. That’s an explicit choice, so it’s respected.
  • No dependencies and no telemetry. It’s a few hundred lines of JavaScript you can read in one sitting.

What it uses on each OS

OSMechanismSee it yourself
WindowsSetThreadExecutionState, called from the built-in Windows PowerShell. Nothing is compiled or written to disk.powercfg /requests
macOScaffeinate -i -w <pid>, tied to VS Code’s lifetimepmset -g assertions
Linuxsystemd-inhibit and, on GNOME, gnome-session-inhibitsystemd-inhibit --list

Measured on a Windows 11 laptop over ten minutes: after start-up, the helper used 0.05 seconds of CPU in total (under 0.01% of one core) and about 7 MB of memory. Starting it takes about a second, once. The extension itself never polls, and in the default mode it doesn’t listen for any activity events.

Optional

Smarter, if you want it

By default it keeps the machine awake whenever VS Code is open: simple and predictable. If you leave VS Code open all day and want the laptop to sleep once the agents are done, switch on activity mode. The machine then stays awake while files are changing or a terminal command, task or debug session is running, plus 30 minutes, and then lets it sleep.

Get it

Two minutes, then forget about it

  1. Download the .vsix from the latest release.
  2. Run code --install-extension agent-keep-awake-1.0.0.vsix, or use Extensions → … → Install from VSIX…
  3. Look for the cup in the status bar. That’s it.
